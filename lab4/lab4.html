4. Compacter avec OPTIMIZE, nettoyer avec VACUUM

Chaque écriture ajoute des fichiers : une table alimentée par petits lots finit avec beaucoup de petits fichiers, coûteux à lire. OPTIMIZE les regroupe ; ZORDER BY range en plus les valeurs proches de la colonne choisie dans les mêmes fichiers, pour que le data skipping ignore les fichiers inutiles lors d'un filtre sur cette colonne. On travaille sur une table d'essai, pour ne pas toucher à Silver.

Databricks · Python
from pyspark.sql import functions as F

# Table d'essai écrite en 5 petits lots : 5 commits, donc au moins 5 fichiers
src = spark.table("silver_transactions")
spark.sql("DROP TABLE IF EXISTS essai_fichiers")
for i in range(5):
    (src.filter(F.abs(F.hash("client_id")) % 5 == i)
        .write.mode("append").saveAsTable("essai_fichiers"))

VACUUM essai_fichiers DRY RUN
Le DRY RUN liste les fichiers que VACUUM supprimerait, sans rien supprimer.
N'exécutez pas VACUUM … RETAIN 0 HOURS : Delta le refuse par défaut, car on perdrait le time travel et on risquerait de supprimer les fichiers d'une écriture en cours. La durée de rétention par défaut est de 7 jours.
Sur des tables aussi petites, aucun gain de temps n'est mesurable : on observe le compactage. Pour une nouvelle table, Databricks recommande aujourd'hui le liquid clustering (CLUSTER BY) plutôt que le partitionnement et ZORDER (chapitre 3, partie 4).

Question de validation

Quel mécanisme rend un rechargement idempotent dans Silver ?

Répondez à la question de validation pour débloquer ce bouton.

À la section 1, rejouer l'ingestion en append a doublé la table. Ici, on rejoue un lot dans Silver avec MERGE : le nombre de lignes ne doit pas changer.

Databricks · SQL
%sql
CREATE OR REPLACE TEMP VIEW lot AS SELECT * FROM silver_transactions;   -- même lot, rejoué

MERGE INTO silver_transactions AS s
USING lot AS l
  ON s.transaction_id = l.transaction_id
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *;

SELECT COUNT(*) AS nb_lignes FROM silver_transactions;
Databricks · SQL
%sql
CREATE OR REPLACE TEMP VIEW lot AS SELECT * FROM silver_evenements;      -- même lot, rejoué

MERGE INTO silver_evenements AS s
USING lot AS l
  ON s.colis_id = l.colis_id AND s.etape = l.etape AND s.ts = l.ts
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *;

SELECT COUNT(*) AS nb_lignes FROM silver_evenements;

  • TABLE_OR_VIEW_NOT_FOUND : exécutez la cellule USE CATALOG workspace / USE SCHEMA lab4 (section 0).
  • La table Bronze contient deux fois trop de lignes : refaites le RESTORE … TO VERSION AS OF 0, puis rejouez Silver et Gold.
  • SyntaxError ou PARSE_SYNTAX_ERROR : il reste un ___ dans votre code.
  • Le bilan ne tombe pas juste : vérifiez la clé de dropDuplicates et que la quarantaine reçoit bien toutes les lignes non valides.
  • Erreur de conversion (CAST_INVALID_INPUT ou équivalent) : un cast a été écrit à la place d'un try_cast.
  • Une fenêtre filtrée dans le même SELECT échoue : calculez le rang dans une CTE, puis filtrez dans la requête suivante.
