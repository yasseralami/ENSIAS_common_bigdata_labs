Vos données arrivent « à plat » : un document par transaction, par scan ou par vente. On construit ici, avec un pipeline d'agrégation terminé par $out, une collection où les éléments liés sont imbriqués dans un document parent (chapitre 5, partie 4).

Un document par compte émetteur, avec le tableau de ses envois.

Un document par colis, avec le tableau de ses événements et les informations du référentiel (jointure $lookup).

Un document par magasin et par semaine, avec le tableau des ventes de la semaine (motif « bucket »).

Répondez à la question de validation pour débloquer ce bouton.

Sans index, MongoDB lit tous les documents (étape COLLSCAN). Avec un index adapté, il parcourt l'index puis ne lit que les documents visés (IXSCAN puis FETCH). Cette fonction résume le plan renvoyé par explain("executionStats") ; collez-la une fois dans mongosh :

mongosh
function etapes(e) {
  var p = e.queryPlanner.winningPlan; p = p.queryPlan || p;
  var r = []; while (p) { r.push(p.stage); p = p.inputStage; }
  var s = e.executionStats;
  return { plan: r.join(" > "), docs_examines: s.totalDocsExamined,
           cles_examinees: s.totalKeysExamined, renvoyes: s.nReturned };
}
