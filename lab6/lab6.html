1. Kafka Connect : d'un fichier à un autre (annexe A)

Les connecteurs FileStream ne sont pas chargés par défaut : déclarez leur dossier, créez un fichier source, puis lancez deux connecteurs en mode autonome.

  config/connect-file-source.properties config/connect-file-sink.properties

En cas de problème

Kafka

  • jps n'affiche pas Kafka après le démarrage, et le journal mentionne NodeExistsException : ZooKeeper garde l'enregistrement du broker de la session précédente. Attendez 20 secondes, puis relancez le broker seul :
    cluster-master
    $KAFKA_HOME/bin/kafka-server-start.sh -daemon $KAFKA_HOME/config/server.properties
jps
  • Topic … already exists : le topic a été créé lors d'une séance précédente ; continuez.
  • NoBrokersAvailable (Python) ou Connection refused : Kafka n'est pas démarré (voir ci-dessus).
  • Le simulateur ne publie rien pendant au plus une minute : c'est normal, il attend le début de la minute suivante.

Python et MongoDB

  • Kafka UI affiche le cluster hors ligne ou aucun topic : vérifiez que Kafka tourne (jps, section 0), puis rechargez la page. Le port 8080 ouvre l'interface de Spark, pas Kafka UI (port 8081).
  • No module named pip ou kafka : refaites l'installation de la section 0 dans ce conteneur (elle est perdue si le conteneur est recréé).
  • Définissez d'abord MONGO_URI : la variable n'existe que dans le terminal où vous avez fait l'export ; refaites-le.
  • ServerSelectionTimeoutError : l'adresse 0.0.0.0/0 manque dans Network Access, ou le cluster Atlas est en pause (reprenez-le dans Atlas).
  • Document failed validation : un champ ne respecte pas le validateur ; vérifiez que vous n'avez modifié que les ___.

Spark

  • $SUBMIT vide (alertes_lab6.py: command not found) : refaites l'export SUBMIT=… de la section 4 dans ce terminal.
  • Échec du téléchargement du connecteur (unresolved dependency) : vérifiez l'accès Internet du Codespace et relancez ; les jars sont ensuite gardés dans /root/.ivy2.
  • NameError ou SyntaxError sur ___ : il reste un trou dans votre règle.
  • Aucune alerte (2SCL, BI&A) : le simulateur doit tourner, car une fenêtre n'est close que lorsque des événements plus récents arrivent (watermark).
  • Après une modification de la règle, Spark refuse de repartir du point de reprise (checkpoint) : supprimez le dossier /tmp/lab6-chk-… de l'étape concernée.
