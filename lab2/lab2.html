spark-submit soumet une application à Spark, quel que soit le mode d'exécution. On commence par l'exemple SparkPi fourni avec Spark, qui estime π par tirages aléatoires. Son paramètre est le nombre de partitions.

1. En mode local, sur le seul conteneur maître

cluster-master
ls $SPARK_HOME/examples/jars/ | grep examples

spark-submit --class org.apache.spark.examples.SparkPi --master "local[*]" \
  $SPARK_HOME/examples/jars/spark-examples_*.jar 10 2>/dev/null | grep "Pi is"
Une seule ligne : Pi is roughly …. Le 2>/dev/null masque les journaux techniques de Spark.

2. Sur le cluster, avec YARN

cluster-master
spark-submit --class org.apache.spark.examples.SparkPi --master yarn --deploy-mode client \
  $SPARK_HOME/examples/jars/spark-examples_*.jar 100 2>&1 | grep -E "Pi is|Submitted application"
Deux lignes : l'identifiant application_… attribué par YARN, puis la valeur de π. Dans l'interface YARN (8088), l'application Spark Pi apparaît avec l'état FINISHED.

Restez dans le même shell pyspark qu'à la section 3 : la variable ventes y est définie. Si vous l'avez quitté, relancez pyspark --master "local[*]" puis la commande ventes = sc.textFile(…) de la section 3.

2. Avec l'API DataFrame

cluster-master · pyspark
from pyspark.sql import functions as F

schema = "date_vente DATE, heure STRING, magasin STRING, categorie STRING, montant DOUBLE, paiement STRING"
df = spark.read.csv("hdfs://hadoop-master:9000/user/root/input/purchases.txt", sep="\t", schema=schema)
df.printSchema()
df.show(3)

res = (df.groupBy("magasin")
         .agg(F.round(F.sum("montant"), 2).alias("ca"))
         .orderBy(F.desc("ca")))
res.show(3)
res.explain()

cluster-master · pyspark

""").show()

En cas de problème
  • spark-submit: command not found ou pyspark: command not found : vous êtes dans le terminal Codespace. Entrez dans le maître avec docker exec -it cluster-master bash.
  • Connection refused sur le port 9000 : HDFS n'est pas démarré. Relancez ./start-hadoop.sh depuis le maître.
  • L'application reste à l'état ACCEPTED dans YARN : une autre application occupe les ressources. Listez-les avec yarn application -list et arrêtez l'ancienne avec yarn application -kill <id>.
  • Le port 4040 n'apparaît pas : le Spark UI n'existe que pendant qu'une application tourne. Si deux applications tournent, la seconde utilise le port 4041.
  • Python in worker has different version : lancez export PYSPARK_PYTHON=python3 dans le maître, puis relancez la commande.
  • Le Codespace ne démarre pas : prévenez l'enseignant. En secours, les sections 2 à 4 peuvent se faire dans Google Colab (!pip install pyspark, mode local, fichiers téléversés dans la session).
